## Goal

Build a local, read-only Model Context Protocol (MCP) server that provides intelligent, contextual, and historical code review assistance for repositories across the UFS-Chem ecosystem:

1. **Local MCP Server over STDIO**: Easy to run locally against a PR created on GitHub (or a local git diff). Exposes MCP tools, resources, and prompts to any MCP-compliant client (Claude Desktop, Cursor, Antigravity, VS Code Copilot Agent, Gemini CLI) with explicit `readOnly: True` metadata.
2. **Zero Runtime LLM inside the MCP server**: Following `omd-docs-mcp`, the server does **not** invoke any local or remote LLMs during retrieval or evaluation. It serves deterministic, classified historical evidence, rule-based audits, and structured context so the user's *chosen client LLM* performs the final synthesis without redundant latency, cost, or hidden hallucinations.
3. **Historical PR Knowledge Base (SQLite + FTS5)**: Scans, parses, and indexes historical PR comments, discussion threads, reviewer identities, and diff follow-ups across 5 core repositories:
   - `ufs-community/CATChem`
   - `ufs-community/CECE`
   - `ufs-community/ufs-chem-container`
   - `benkozi/ufs-chem-assay`
   - `bbakernoaa/HELM-Project`
4. **Follow-Up Diff Tracking & Criticality Scoring**: Tracks whether a historical comment prompted a code change in subsequent commits (`has_diff_followup`) vs mere discussion, along with language detection, reviewer identity, and criticality ranking (1 to 5).
5. **Deterministic Relevance Ranking (`match_score`)**: Scores and ranks historical comments before returning them to the client LLM using a multi-factor formula combining path proximity, module clustering, actionable diff follow-up bonuses, criticality multipliers, and FTS BM25 relevance.
6. **Ponytail & UFS-Chem Domain Review Rules**: Integrates over-engineering review heuristics from the `ponytail` skill (`delete`, `stdlib`, `native`, `yagni`, `shrink`, net lines removable) alongside UFS-Chem domain checks (CCPP physics interfaces, NUOPC cap conventions, ESMF state sharing, chemistry unit conversions, mass conservation, Fortran `&` continuation handling, and MPI/OpenMP concurrency).
7. **Flexible Review Modes, Output Formatting & Immediate Patch Application**: Supports granular review detail modes (`summary_and_inline`, `summary_only`, `inline_only`) and multi-format schemas enabling the client LLM to format review findings either as:
   - GitHub API-compliant JSON review comment payloads ready to post directly to GitHub (`/repos/{owner}/{repo}/pulls/{pull_number}/reviews`), with 1-click applyable GitHub suggestion markdown blocks (````suggestion\n<replacement>\n````).
   - Clean, readable GitHub Flavored Markdown for human review or pasting into comments.
   - Machine-applicable unified diff patches (`output_format="patch"`) compatible directly with `git apply -` or local agent patch engines.
   - Always accompanied by a critical summary highlighting high-risk catches and over-engineering findings.
8. **Configurability & Refresh Automation**:
   - Source repository list is configurable via YAML/JSON.
   - Built-in incremental sync CLI command (`ufs-chem-pr-review-sync`).
   - Weekly GitHub Actions CI job to refresh the database (`.github/workflows/refresh-database.yaml`).
9. **Dedicated Repository CI Testing (`.github/workflows/ci.yaml`)**:
   - CI runs `ufs-chem-pr-review-mcp`'s own dedicated test suite (`tests/`) covering configuration, database storage, diff tracking, classification, rules, CLI, and MCP server endpoints.
   - Enforces a strict 100% code coverage requirement in CI (`--cov-fail-under=100`) for all mock unit tests. Live network tests are isolated under `@pytest.mark.integration` and deselected by default.
10. **Standardized Logging & Zero Stdout Pollution**:
    - Centralized namespace logging (`src/ufs_chem_pr_review_mcp/logs.py`) following `ufs-chem-assay`'s `logs.py`.
    - Logging strictly routed to `sys.stderr`, preserving `sys.stdout` exclusively for the MCP STDIO JSON-RPC wire.
    - Zero `print()` statements across `src/` (enforced via ruff rule `T201` / `flake8-print`).

   - `CECE` (Chemistry Evaluation & Verification Engine): Fortran, C++, NetCDF interfaces, CMake. Common review topics: driver coupling, time-stepping, driver state initialization.
   - `ufs-chem-container`: Dockerfile, Apptainer/Singularity recipes, bash scripts, Spack specs. Common review topics: container layer optimization, environment variables, compiler flags, non-root user permissions.
   - `ufs-chem-assay`: Python 3.11+, pytest combinatorial suites, xarray, cartopy, pydantic, Slurm HPC runner scripts. Common review topics: harness test isolation, baseline verification, S3 data staging.
   - `HELM-Project`: Atmospheric chemistry workflows, Python, Shell, YAML configs. Common review topics: job orchestration, runtime environment configuration.
4. **Ponytail Review Skill Analysis**:
   - Reviewed from `/Users/bkoziol/.gemini/config/plugins/ponytail/skills/ponytail-review/SKILL.md`.
   - Core philosophy: Review for over-engineering only, not correctness.
   - One line per finding: `L<line>: <tag> <what to cut>. <replacement>.`
   - Canonical Tags:
     - `delete`: dead code, speculative features, unused parameters or imports.
     - `stdlib`: reinventing what standard libraries provide.
     - `native`: third-party dependency doing what the core language or platform already does.
     - `yagni`: unnecessary abstraction with only one implementation or speculative generality.
     - `shrink`: same logic expressed in fewer lines and less complexity.
   - Metric: Net lines and dependencies removable. If lean: `"Lean already. Ship."`
5. **GitHub Review API Mechanics**:
   - POST `/repos/{owner}/{repo}/pulls/{pull_number}/reviews`:
     - `commit_id`: SHA of the commit being reviewed.
     - `body`: Markdown review summary.
     - `event`: `"APPROVE"`, `"REQUEST_CHANGES"`, or `"COMMENT"`.
     - `comments`: list of objects with `path`, `line`, `side` (`"RIGHT"`), `body`.
   - GraphQL API v4: Pull request review threads (`PullRequestReviewThread`) provide `isResolved`, comments list, line numbers, and original commits.
   - Tracking diff follow-ups: When a review comment is created at timestamp $t$, subsequent commits in the PR (`commit.timestamp > t`) can be compared against the file and line range of the comment. If the lines were modified or deleted, `has_diff_followup = True`.

## Design

### 0. Decisions

- **Package & Dependency Strategy**:
  - `python>=3.11`.
  - Dependencies: `mcp>=1.12,<2`, `pydantic>=2.7`, `pydantic-settings>=2.2`, `httpx>=0.27` (async HTTP client with connection pooling for GitHub API), `pyyaml>=6.0`.
  - Dev dependencies: `pytest>=8.0`, `pytest-mock>=3.14`, `pytest-cov>=5.0`, `pytest-asyncio>=0.23`, `respx>=0.21` (mocking httpx requests), `mypy>=1.14`, `ruff>=0.12,<0.13`, `pre-commit>=4.0`, `yamlfix>=1.16`, `yamllint>=1.35`.
  - Build system: `hatchling` with project layout `src/ufs_chem_pr_review_mcp/`.
- **Database Engine: SQLite with FTS5 (`sqlite3`)**:
  - Standard library, zero external server requirement, local single-file database (`data/ufs_chem_reviews.sqlite3`).
  - Full-Text Search via SQLite FTS5 extension enables sub-millisecond keyword and fuzzy matching across thousands of historical review comments.
  - Automatic indexing on `repo`, `language`, `category`, `criticality`, `has_diff_followup`, and `created_at`.
- **Ingestion & Serving Separation**:
  - `src/ufs_chem_pr_review_mcp/server.py`: Fast, read-only MCP server over STDIO. Opens SQLite with `PRAGMA query_only = ON;`.
  - `src/ufs_chem_pr_review_mcp/cli/sync.py`: Standalone CLI entrypoint (`ufs-chem-pr-review-sync`) for pulling new comments, running diff follow-up detection, and pruning stale records.
- **Deterministic Historical Relevance Scoring (`match_score`)**:
  - Prioritizes comments using a deterministic formula: exact file match ($+50$), parent module/directory ($+25$), language ($+10$), actionable follow-up ($+20$), criticality multiplier ($+5 \times \text{criticality}$), and BM25 rank. Guarantees that highest-signal catches reach the LLM first.
- **Fortran Continuation Line Normalization (`&`)**:
  - When analyzing Fortran additions, multi-line statements connected by `&` are collapsed into single logical expressions before evaluating chemistry units and Ponytail rules, preserving exact source line coordinates for findings.
- **Review Mode Granularity (`ReviewMode`)**:
  - Exposes `SUMMARY_AND_INLINE` (default), `SUMMARY_ONLY` (quick triage, no inline spam), and `INLINE_ONLY` modes.
- **MCP Tool Read-Only Annotations**:
  - Declares `readOnly: True` metadata on all retrieval tools in `server.py`, signaling to MCP client hosts (Cursor, Claude Desktop, Antigravity) that tool invocations are safe to auto-execute without interactive approval modals.
- **Machine-Applicable Patch Generation (`OutputFormat.PATCH` & `CodePatch`)**:
  - Bridges the gap between passive code review and autonomous patch application.
  - Automatically synthesizes RFC-compliant unified diff hunks (`@@ -start,len +start,len @@`) with git headers (`diff --git a/... b/...`) suitable directly for `git apply -` or local agent tool ingestion (`replace_file_content`).
  - Prepares GitHub suggestion blocks (````suggestion\n<replacement>\n````) on `GitHubInlineComment` payloads, allowing 1-click commit application in the GitHub PR web interface.
  - Generates concrete replacements from both Ponytail heuristics (deleting dead imports, replacing verbose loops with array syntax) and UFS-Chem domain rules (adding missing `stat=rc` checks, multiplying by molecular weight ratio).
- **Standardized Logging Architecture (`src/ufs_chem_pr_review_mcp/logs.py`)**:
  - Centralized namespace logger (`ufs_chem_pr_review_mcp`) modeled after `ufs-chem-assay/src/logs.py`.
  - All application modules (`server.py`, `cli/sync.py`, `ingest/`, `db/`, `rules/`) obtain loggers exclusively via `get_logger(__name__)`.
  - Zero raw `print()` statements across `src/` (enforced by ruff lint rule `T201` / `flake8-print`).
  - Output is strictly directed to `sys.stderr`, guaranteeing that the MCP STDIO transport on `sys.stdout` remains pristine and free from frame corruption.
- **Classification Taxonomy**:
  - Categories:
    - `overengineering`: Ponytail violations (dead code, excessive abstraction, reinvented wheel).
    - `correctness`: Off-by-one, memory leaks, uninitialized variables, array bounds, pointer bugs.
    - `chemistry_physics`: Unit mismatches (ppmv vs kg/kg, STP vs ambient), molecular weights, emission factors, photolysis indices, mass conservation.
    - `esmf_nuopc`: NUOPC Cap conventions, ESMF state sharing, field dictionary naming, grid discretization mismatches.
    - `concurrency_hpc`: MPI communication deadlocks, OpenMP race conditions, memory bandwidth, GPU/Kokkos offloading caveats.
    - `build_packaging`: CMake dependencies, Spack specs, Dockerfile layers, compiler incompatibility.
    - `ci_testing`: Test coverage, harness integration, baseline drift.
    - `style_docs`: Conventions, naming, formatting.
  - Criticality Scale:
    - `5` (Blocker / Bug / Crash): Calculation error, deadlock, invalid chemistry, memory corruption.
    - `4` (Major): Logic flaw under specific boundary conditions, memory leak, unverified physical units.
    - `3` (Moderate): Over-engineering, poor performance, missing error checks.
    - `2` (Minor): Style inconsistency, missing comments or docs.
    - `1` (Nit): Formatting, typo.
- **Client LLM Parsing Role**:
  - The MCP server does **not** make LLM calls. It extracts the PR diff, retrieves matching historical review comments, applies regex/AST-based ponytail checks and domain heuristics, and returns a rich, structured Pydantic-validated JSON payload.
  - The user's client LLM reads this structured context, reviews the PR diff with grounded historical evidence, and produces the final review comments in either GitHub Review API JSON format or GitHub Markdown.
- **Coverage & Test Isolation Policy**:
  - 100% line and branch coverage required for all dedicated mock unit tests in `tests/` via `pytest-cov --cov=src/ufs_chem_pr_review_mcp --cov-fail-under=100`.
  - Integration tests calling real GitHub endpoints (`tests/test_integration_live_gh.py`) require `@pytest.mark.integration` and are deselected by default in `pytest.ini_options` via `addopts = ["--strict-markers", "-m", "not integration"]`.
- **Lean CI Scope (No Unnecessary External Matrix)**:
  - `.github/workflows/ci.yaml` runs `ufs-chem-pr-review-mcp`'s own dedicated tests directly.
  - Avoids YAGNI over-engineering: no complex 5-repository matrix workflow. All historical review fixtures and domain rules are tested cleanly and deterministically within `tests/`.

#### Relevance Scoring Function (`src/ufs_chem_pr_review_mcp/db/repository.py`)
To prevent historical retrieval noise, `query_relevant_comments()` computes a deterministic score for candidate comments matching touched files and identifiers:
$$\text{match\_score} = \text{PathProximity} + \text{FollowUpBonus} + (5.0 \times \text{criticality}) + \text{BM25Rank}$$
- **Exact Path Match**: $+50.0$ if `comment.path` matches an exact file touched in the diff.
- **Parent Module Match**: $+25.0$ if `comment.path` shares the same directory or module prefix.
- **Language Match**: $+10.0$ if the commented file shares the same language.
- **Actionable Follow-up Bonus**: $+20.0$ if `has_diff_followup = True` (heavily prioritizes comments that resulted in confirmed code changes).
- **Criticality Multiplier**: $5.0 \times \text{criticality}$ ($+5.0$ to $+25.0$ pts).
- **BM25 Text Match**: Scaled addition ($0.0$ to $+15.0$) based on SQLite FTS5 `bm25()` rank over identifiers in the diff.
The top `max_context_comments` sorted by `match_score DESC` are returned in `ReviewContextResponse`.

#### Pruning Mechanics (`src/ufs_chem_pr_review_mcp/db/pruning.py`)
- Database pruning function `prune_database(conn: sqlite3.Connection, retention_days: int | None = None, max_records_per_repo: int | None = None) -> int`.
- Safely removes stale closed unmerged PRs or comments older than the retention threshold using `created_at` and `indexed_at`.
- Cascading foreign keys ensure children in `review_comments` and FTS index entries are cleaned automatically.

### 4. GitHub Ingestion & Refresh Engine

#### `src/ufs_chem_pr_review_mcp/ingest/client.py`
- Built on `httpx.AsyncClient` with authentication via `GITHUB_TOKEN` environment variable.
- Supports both REST API (`/repos/{owner}/{repo}/pulls`, `/pulls/{pull_number}/comments`, `/pulls/{pull_number}/commits`) and GraphQL API for review thread status (`PullRequestReviewThread.isResolved`).
- Handles GitHub API rate limits transparently:
  - Checks `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers.
  - Implements exponential backoff on HTTP 403 / 429.
  - Implements HTTP ETag conditional requests (`If-None-Match`) to avoid consuming rate limit quota on unchanged resources.

#### `src/ufs_chem_pr_review_mcp/ingest/diff_tracker.py`
Follow-up diff association engine and statement normalizer:
1. **Fortran Continuation Line Normalization (`&`)**:
   - Helper `normalize_fortran_statements(lines: list[str]) -> list[tuple[str, int]]`:
   - Scans diff added lines for trailing ampersands `&` (ignoring trailing `!` comments). Joins continued lines into a unified logical statement while mapping the combined expression to its primary starting diff line number.
   - Prevents multi-line chemical equations, array bounds, or subroutines from bypassing regex checks.
2. **Diff Follow-up Tracking**:
   - For each review comment at timestamp $T_{\text{comment}}$ referencing file $P$ and diff line $L$:
   - Query commits in the PR where $T_{\text{commit}} > $T_{\text{comment}}$.
   - Fetch the commit file patches. If any subsequent commit touches file $P$ within a window of $L \pm 10$ lines (or deletes the referenced code block):
     - `has_diff_followup = True`
     - `diff_followup_status = DiffFollowUpStatus.CODE_MODIFIED`
   - If no subsequent commit touches file $P$, inspect thread replies:
     - If author replied with explanation or resolved thread: `DiffFollowUpStatus.REJECTED_EXPLAINED` or `DiffFollowUpStatus.DISCUSSION_ONLY`.
     - If no reply: `DiffFollowUpStatus.NO_RESPONSE`.
     - `has_diff_followup = False`.

#### `src/ufs_chem_pr_review_mcp/ingest/classifier.py`
Automated categorization and criticality ranking without requiring an LLM:
1. **Language Detection**: Derived from file extension (`.F90`, `.f90`, `.inc` $\rightarrow$ Fortran; `.cpp`, `.hpp`, `.cc` $\rightarrow$ C++; `.py` $\rightarrow$ Python; `CMakeLists.txt`, `.cmake` $\rightarrow$ CMake; `Dockerfile`, `Containerfile` $\rightarrow$ Dockerfile; `.sh`, `.bash` $\rightarrow$ Shell; `.yaml`, `.yml` $\rightarrow$ YAML). Disambiguates `.h`/`.inc` via content heuristics.
2. **Category Classification**: Deterministic regex and keyword matching over the comment body:
   - `chemistry_physics`: keywords `unit`, `ppm`, `ppb`, `kg/kg`, `molar`, `molecular weight`, `emission`, `aerosol`, `photolysis`, `stoichiometry`, `half-life`, `reaction rate`.
   - `esmf_nuopc`: keywords `nuopc`, `esmf`, `cap`, `advertise`, `realize`, `importstate`, `exportstate`, `field dictionary`, `coupling`, `clock`, `alarm`.
   - `concurrency_hpc`: keywords `mpi_`, `openmp`, `thread`, `deadlock`, `barrier`, `race condition`, `kokkos`, `offload`, `cuda`, `gpu`, `bandwidth`.
   - `overengineering`: keywords `yagni`, `over-engineered`, `unused`, `dead code`, `unnecessary abstraction`, `wrapper`, `simplify`, `boilerplate`, `native`.
   - `correctness`: keywords `bug`, `crash`, `segfault`, `out of bounds`, `uninitialized`, `leak`, `memory leak`, `null`, `nullptr`, `nan`, `infinity`, `off-by-one`.
   - `build_packaging`: keywords `cmake`, `spack`, `compiler`, `docker`, `container`, `target_link_libraries`, `find_package`, `build error`.
   - Default fallback: `style_docs`.
3. **Criticality Ranking (1 to 5)**:
   - Score 5: Mentions crash, segfault, invalid physics/chemistry, data corruption, security vulnerability, AND has `has_diff_followup = True`.
   - Score 4: Mentions memory leak, uninitialized variable, off-by-one, deadlock, or test failure AND has `has_diff_followup = True`.
   - Score 3: Performance, over-engineering / simplification suggestions, missing edge cases.
   - Score 2: Minor refactoring, naming conventions, documentation gaps.
   - Score 1: Whitespace, spelling, trivial style nits.

### 5. Review Context Classification & Ponytail Analysis

#### `src/ufs_chem_pr_review_mcp/rules/ponytail.py`
Static rule engine inspired by the `ponytail-review` skill, executed directly against diff hunks:
- **`delete` Rule**:
  - Unused imported symbols (Python `import`, Fortran `use ... only:`, C++ `#include`).
  - Commented-out dead code blocks in new additions.
  - Speculative utility functions added without any call site in the PR diff.
- **`stdlib` Rule**:
  - Reimplementing standard library routines (e.g., custom string splitting, home-grown min/max or sorting, custom path concatenation when `pathlib` / `std::filesystem` exists).
- **`native` Rule**:
  - Introducing heavy dependencies for trivial operations (e.g. adding a 3rd party package for basic JSON parsing or math calculations).
- **`yagni` Rule**:
  - Single-implementation abstract base classes / interfaces.
  - Factory functions or strategy patterns where only one concrete variant exists.
  - Speculative configuration flags or CLI parameters not referenced anywhere in execution logic.
- **`shrink` Rule**:
  - Verbose boilerplate that can be collapsed into standard idiomatic constructs (e.g., Python list comprehensions, ternary operators, modern Fortran array syntax `a(:) = 0.0`).
- **Formatting & Patch Construction**:
  - Emits `PonytailFinding` objects with exact line numbers, tags, cut descriptions, replacements, and lines saved.
  - Automatically extracts `original_code` from the diff hunk and generates `replacement_code` (e.g. empty string for `delete`, stdlib alternative for `stdlib`).
  - Constructs a valid `CodePatch` with RFC unified diff hunk syntax (`@@ -start,len +start,len @@`) for machine application.
  - If no findings exist: `"Lean already. Ship."`

#### `src/ufs_chem_pr_review_mcp/rules/ufs_chem.py`
Specialized domain rules for UFS atmospheric chemistry code:
- **Atmospheric Chemistry Units**:
  - Flags conversions between molar mixing ratios (mol/mol, ppmv, ppbv) and mass mixing ratios (kg/kg) lacking molecular weight normalization ($M_{\text{spec}} / M_{\text{air}}$ where $M_{\text{air}} \approx 28.964 \text{ g/mol}$).
  - Flags emissions calculations missing grid cell area or timestep scaling.
- **ESMF / NUOPC Cap Correctness**:
  - Flags `ESMC_StateGet` / `ESMF_StateGet` calls lacking proper return code checks (`ESMF_LogFoundError`).
  - Verifies that advertised fields are realized before state exchanges.
- **Fortran Numerical & HPC Safety**:
  - Flags single-precision literals (e.g. `1.0` instead of `1.0_rk` or `1.0d0`) in double-precision floating-point chemistry calculations.
  - Flags array dimension order in nested loops that violate Fortran column-major memory ordering (outer loop over first index, inner loop over last index $\rightarrow$ cache thrashing).
  - Flags allocate statements without `stat=` and `errmsg=` checks.
- **Formatting & Patch Construction**:
  - Emits `DomainFinding` objects with exact line coordinates, domain category, criticality, and explanation.
  - Provides `original_code` and corrected `replacement_code` (e.g. converting single-precision `1.0` to `1.0_rk`, or adding `stat=rc, errmsg=msg` to Fortran `allocate`).
  - Attaches a pre-computed `CodePatch` ready for instantaneous patching via `git apply`.

### 7. Configuration, Settings & Standardized Logging

#### `src/ufs_chem_pr_review_mcp/logs.py`
Standardized logging module for the repository. Following `ufs-chem-assay/src/logs.py`, this defines a single namespace logger, level configuration from settings, and explicit output to `sys.stderr` to prevent stdout pollution:
```python
"""Standardized logging for ufs-chem-pr-review-mcp: single namespace, level from settings,
strictly outputting to sys.stderr to guarantee zero stdout pollution for the MCP JSON-RPC transport."""

import logging
import sys
from typing import TextIO

LOGGER_NAME = "ufs_chem_pr_review_mcp"
_FORMAT = "%(asctime)s [%(levelname)s] %(name)s: %(message)s"


def get_logger(name: str) -> logging.Logger:
    """Return a child logger under the top-level namespace."""
    return logging.getLogger(f"{LOGGER_NAME}.{name}")


def configure_logging(level: str = "INFO", stream: TextIO = sys.stderr) -> None:
    """Configure the namespace logger once per session (idempotent).
    Guarantees that log messages never touch sys.stdout."""
    logger = logging.getLogger(LOGGER_NAME)
    logger.setLevel(level.upper())
    if not logger.handlers:
        handler = logging.StreamHandler(stream)
        handler.setFormatter(logging.Formatter(_FORMAT))
        logger.addHandler(handler)
```

**Logging Conventions Across the Application**:
- Every module (`server.py`, `cli/sync.py`, `ingest/`, `db/`, `rules/`) initializes its logger via:
  ```python
  from ufs_chem_pr_review_mcp.logs import get_logger
  logger = get_logger(__name__)
  ```
- **DEBUG**: Low-level diagnostics (SQL queries, diff hunk boundaries, commit evaluations, ETag cache hits).
- **INFO**: High-level workflow milestones (server started, PR evaluated, sync completed, records ingested).
- **WARNING**: Recoverable edge cases (unauthenticated GitHub rate limit warnings, skipped binary files, fallback classifications).
- **ERROR**: Handled process failures (GitHub API HTTP errors, database write exceptions, diff syntax parsing failures).
- **Zero Raw `print()` Statements**: Raw `print()` is strictly prohibited in `src/` to prevent JSON-RPC transport corruption. Enforced in pre-commit and CI via ruff rule `T201` (`flake8-print`).

### 9. Edge Cases, Guards & Error Handling

A systematic audit across all architectural layers identified 12 edge cases, each paired with concrete architectural guards and test assertions:

1. **FTS5 Syntax Error & Special Character Escaping (Code Punctuation in Queries)**:
   - *Scenario*: Users or client LLMs search for code symbols containing operators: `ESMF_StateGet(state, "tracer")`, `Chem_Init::run()`, `x - y`, `ptr->val`, `!$omp`.
   - *Risk*: SQLite FTS5 parser treats `(`, `)`, `:`, `-`, `*`, `AND`, `OR`, `NOT`, `^` as query operators. Unescaped queries cause `sqlite3.OperationalError: fts5: syntax error near ...`.
   - *Guard*: A dedicated FTS query sanitizer function `sanitize_fts_query(query: str) -> str` in `src/ufs_chem_pr_review_mcp/db/repository.py`. Strips unbalanced quotes, removes dangerous FTS operators, and wraps code tokens in double-quoted phrases joined by implicit AND (`"ESMF_StateGet" "state" "tracer"`).
   - *Test*: `test_db.py` asserts queries with parentheses, dashes, colons, arrows, and unbalanced quotes execute cleanly without SQL syntax errors.

2. **MCP STDIO JSON-RPC Stream Corruption (Rogue stdout Pollution)**:
   - *Scenario*: Third-party dependencies or diagnostic `print()` statements write to standard output during MCP tool execution.
   - *Risk*: The MCP protocol framing over STDIO relies on pure JSON-RPC messages delimited by newlines or headers. Any non-JSON text on `sys.stdout` corrupts the transport and immediately crashes client connections (Claude Desktop, Cursor, Antigravity).
   - *Guard*: Server startup in `src/ufs_chem_pr_review_mcp/server.py` and `logs.configure_logging()` binds all logging handlers exclusively to `sys.stderr`. Stdout is reserved strictly for the MCP stdio transport. Ruff rule `T201` forbids `print()` across `src/`.
   - *Test*: `test_mcp_server.py` captures stdout during tool calls and asserts every byte emitted is valid JSON-RPC.

3. **PR Force-Pushes, Squashed Commits & Line Displacements in Follow-up Diffs**:
   - *Scenario*: A PR author force-pushes or rebases after a review comment, or the PR is squash-merged, or adds lines at the top of a file, shifting line numbers downstream.
   - *Risk*: Follow-up commit SHAs may disappear or line numbers no longer align with the original comment's `line`.
   - *Guard*: Diff tracker uses a multi-stage resolution strategy:
     1. Compares line window: $L \pm 10$ lines in subsequent commits.
     2. Fallback to `is_resolved` status from GitHub GraphQL review threads.
     3. Fallback to PR final merge commit diff: checks whether the hunk in `path` changed between comment time and merge.
   - *Test*: `test_diff_tracker.py` tests line shift, force-push SHA disappearance, and squash-merge scenarios.

4. **Multiline Comments and `LEFT` (Base) vs `RIGHT` (Head) Diff Sides**:
   - *Scenario*: Reviewer comments on deleted lines on the left side of the diff (`side="LEFT"`), or spans a range (`start_line=10, line=15`).
   - *Risk*: Assuming comments only target single lines on the right side causes incorrect line tracking or missing line coordinates.
   - *Guard*: `ReviewCommentRecord` models `side` (`"LEFT"` | `"RIGHT"`) and optional `start_line`. Follow-up tracker checks deletion hunks in subsequent commits for `LEFT`-side comments.
   - *Test*: `test_models.py` and `test_diff_tracker.py` verify multiline and `LEFT`-side comment parsing.

5. **GitHub API 3,000-Line Unified Diff Truncation (`too_large`)**:
   - *Scenario*: PRs touching large files, vendored dependencies, or dataset configs exceed GitHub's single unified diff limit (3,000 lines or 300 files).
   - *Risk*: GitHub API omits the diff or returns `too_large`, causing parsing crashes.
   - *Guard*: `ingest/client.py` inspects the PR response. If unified diff is missing or flagged `too_large`, falls back to paginated file diff endpoint (`/pulls/{pr}/files`), skipping binary files (`.nc`, `.png`) and truncated files, logging a clean diagnostic.
   - *Test*: `test_syncer.py` mocks a `too_large` PR response and verifies fallback to paginated file diffs.

6. **Language Ambiguity in Atmospheric Chemistry (`.h`, `.inc`, fixed-format Fortran)**:
   - *Scenario*: CATChem and CECE contain `.h` and `.inc` files that are Fortran include files rather than C/C++ headers. Also, legacy Fortran `.f` files follow fixed-format column rules.
   - *Guard*: `classifier.py` checks file content: if `.h` or `.inc` contains Fortran keywords (`module`, `subroutine`, `implicit none`, `use `), classifies as `FORTRAN`. Normalizes Fortran keywords case-insensitively (`SUBROUTINE` vs `subroutine`).
   - *Test*: `test_classifier.py` verifies `.h` and `.inc` classification for Fortran vs C/C++.

7. **False-Positive Guards for Ponytail & Domain Rules**:
   - *Scenario*:
     - *Coupled Model Interfaces*: Single-implementation NUOPC or CCPP caps flagged as `yagni`.
     - *Standard API Dummy Arguments*: Standard subroutines requiring unused arguments (`rc`, `clock`) flagged as `delete`.
     - *HPC Loop Unrolling*: Explicit loops with OpenMP SIMD directives flagged as `shrink` in favor of whole-array syntax.
   - *Guard*: Rule engines implement explicit exemption filters:
     - Whitelist `NUOPC_*`, `ESMF_*`, `cdata`, `rc`, `ccpp_*` parameter patterns.
     - Detect OpenMP SIMD / vectorization directives before flagging loops for `shrink`.
   - *Test*: `test_ponytail_rules.py` tests standard NUOPC cap and SIMD loop snippets, asserting no false positives.

8. **Client LLM Token Budget & Context Window Overflow**:
   - *Scenario*: Returning 15 historical comments with large diff hunks and long thread discussions consumes 20,000+ tokens, exceeding client LLM limits.
   - *Guard*: Bounded payload truncation:
     - Diff hunks truncated to 30 lines / 1,500 characters max per comment with clear truncation marker.
     - Comment body capped at 2,000 characters.
     - `max_context_comments` hard-capped at 50 (default 15).
   - *Test*: `test_mcp_server.py` tests large historical comments and asserts truncation limits are respected.

9. **Database Schema Versioning & Forward/Backward Compatibility**:
   - *Scenario*: Updating local schema (adding columns or triggers) against an existing user `ufs_chem_reviews.sqlite3` file on disk.
   - *Risk*: `sqlite3.OperationalError: no such column: ...`.
   - *Guard*: Schema initializes with `PRAGMA user_version = 1`. On startup, checks `user_version` and executes idempotent schema migrations without clobbering existing indexed data.
   - *Test*: `test_db.py` tests migrating from `user_version = 0` to `user_version = 1`.

10. **Database Relative Path Resolution Across Working Directories**:
    - *Scenario*: Running `ufs-chem-pr-review-mcp` from arbitrary directories (e.g. child directories or unrelated project roots) causes relative path `data/ufs_chem_reviews.sqlite3` to create empty databases in unexpected locations.
    - *Guard*: `Settings.db_path` resolves relative paths against the project root anchor, unless explicitly overridden by an absolute path or `UFS_CHEM_DB_PATH`.
    - *Test*: `test_config.py` verifies resolution from different current working directories.

11. **Testing & Coverage Determinism (Strict 100% Coverage Gate)**:
    - *Scenario*: Generic `except Exception:` catch blocks or unreachable defensive conditions cause `pytest-cov --cov-fail-under=100` to fail CI.
    - *Guard*: Explicit typed exception hierarchy (`UfsChemReviewError`, `GitHubApiError`, `DatabaseError`, `ClassificationError`). No catch-all dead branches. Every error branch is covered by a dedicated test case in `tests/`.
    - *Test*: Mock test suite in `tests/` verifies all error paths.

12. **GitHub Rate Limit Graceful Handling & Non-Crashing Tool Return**:
    - *Scenario*: User runs `evaluate_pr` without a token and hits the 60 req/hr rate limit or provides an expired token.
    - *Risk*: Tool crashes with unhandled HTTP 403, breaking the MCP tool call.
    - *Guard*: `evaluate_pr` catches `GitHubApiError` and returns a structured response with a clear diagnostic message and instructions for setting `UFS_CHEM_GITHUB_TOKEN`, without throwing an unhandled exception to the MCP transport.
    - *Test*: `test_mcp_server.py` tests rate-limit mock response.

13. **Unified Diff & Patch Format Compatibility for `git apply` / Patch Drift**:
    - *Scenario*: The client LLM generates code replacements or the user runs `git apply` on a patch generated from `format_review_output(output_format="patch")`. Multiple patches on the same file may shift downstream line numbers, or lines have differing line-endings (`\r\n` vs `\n`), or missing newline at EOF (`\ No newline at end of file`).
    - *Risk*: `git apply` rejects the patch with `error: patch failed: ...: patch does not apply` or corrupts whitespace.
    - *Guard*:
      - Unified diff hunks are generated sorted by descending line number (or computed against original base content) so applying earlier hunks does not invalidate line offsets for subsequent hunks.
      - Newline normalization (`\n`) and standard RFC unified diff headers (`diff --git a/{path} b/{path}`, `--- a/{path}`, `+++ b/{path}`, `@@ -{start},{len} +{start},{len} @@`).
      - RFC unified diff hunk validation in `CodePatch` ensuring line counts match addition/deletion line counts.
    - *Test*: `test_patch.py` verifies generated patches pass `git apply --check` or diff hunk parsing roundtrips without rejection.

## Risks and notes

- **Zero LLM Boundary**: The MCP server strictly delivers parsed diffs, classified historical comments, and deterministic rule findings. It leaves final linguistic synthesis and comment formatting to the user's client LLM. This prevents token costs and latency inside the server.
- **GitHub Token Security**: `GITHUB_TOKEN` is read from the environment or `.env` and is never logged or exposed via MCP tool outputs.
- **Diff Follow-up Accuracy**: Some PRs squash commits or make wholesale refactors that obscure individual comment line resolutions. The diff tracker uses a $\pm 10$ line window and thread resolution status to provide resilient classification.
- **Database Portability**: The committed SQLite database contains pre-indexed comments from the 5 repositories so fresh clones can run the MCP server immediately without requiring initial sync downloads.

## Resolved decisions

1. **MCP SDK**: `mcp>=1.12,<2` selected, matching `omd-docs-mcp`.
2. **Storage Engine**: SQLite with FTS5 virtual tables (`sqlite3` stdlib) selected for zero external runtime dependencies and instant local search.
3. **No Local LLM**: The server does not host or execute an LLM. Structured JSON/Markdown outputs are prepared for the client agent.
4. **Coverage Standard**: 100% mock test coverage enforced in CI (`pytest-cov --cov-fail-under=100`); live network tests marked `integration` and deselected by default.
5. **Ponytail Integration**: Integrated as a static heuristic engine checking diff hunks for `delete`, `stdlib`, `native`, `yagni`, `shrink`, and line reduction metrics.
6. **Follow-up Diff Metric**: Tracked per comment by checking subsequent commits against modified line ranges, classifying comments into actionable catches vs discussion.
7. **Dedicated Repository CI (`ci.yaml`)**: Focused exclusively on `ufs-chem-pr-review-mcp`'s own test suite (`tests/`). An unrequested 5-repository external matrix workflow was rejected as over-engineering (YAGNI).
8. **Edge Case Architecture**: Comprehensive 12-point edge case mitigation designed into FTS5 query sanitization, stdout stream isolation, multiline/side tracking, schema user_version migrations, token budget limits, and API error shielding.
9. **Standardized Logging (`logs.py`)**: Modeled after `ufs-chem-assay`'s `logs.py`, routing all logs strictly to `sys.stderr` and enforcing zero raw `print()` statements via ruff `T201`.
10. **Relevance Scoring & Continuation Normalization**: Deterministic scoring function (`match_score`) ranking historical comments, Fortran `&` multi-line statement normalization, `ReviewMode` detail granularity, and MCP `readOnly: True` tool metadata.
11. **Machine-Applicable Patch Architecture**: End-to-end support for immediate patch generation. Extended `OutputFormat` with `PATCH` and `ALL`, added `CodePatch` and `PatchResult` models, enhanced findings with `original_code`, `replacement_code`, and `patch`, enabled 1-click GitHub ````suggestion ```` blocks, and added the `generate_patch` MCP tool with descending-line drift guards.
